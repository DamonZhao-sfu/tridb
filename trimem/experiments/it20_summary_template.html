记忆计划能否改变 agent 的结果？

OpenEvolve 0.3.2 + TriMEM 离线经验图 · 5 道 EvoTrace 数学任务 × 种计划 · 每格 20 次迭代（固定计划续跑到 次）· seed 42 · 生成模型 Qwen3.8-27B-FP8（关闭 thinking）。固定记忆计划把检索到的程序替换进 10 个 inspiration 槽位中的 5 个；新优化器（v2）每次迭代从 289 个候选（不注入，或 24 种图遍历配置 × 三种计划家族 × k ∈ {1,3,5,8}）中选一个，最多替换 8 个槽位；quality = combined_score 的历史最优值。

各计划的 quality 与开销（5 道任务平均）

@i = 第 i 次迭代时的历史最优（–：该计划还没跑到）。时间/token/有效比例统计的是前 20 次迭代，所有计划都在同一口径下比较。提升 = 第 20 次迭代的最优分数减去种子分数。有效 = combined_score > 0 的子程序比例。构建 = 离线经验图上一次性的 LLM change summary（embedding、HNSW、lineage/similar 边已经存在），所有记忆计划共享，这里按每道任务全额计入。检索 = embedding + SQL，包括 SemFilter/SemScore 的 LLM 等待。生成 = 各次 agent LLM 调用耗时之和（OpenEvolve 会并发发起请求）。

新优化器（前 20 次迭代）

每次迭代从 289 个候选里选一个：“不注入”，或 图遍历配置（边类型 lineage/similar × 方向 down/up × 1/2 跳 × fanout 4/8/16，共 24 种）× 计划家族（三模态 / 硬过滤 / 排序加权）× k ∈ {1,3,5,8}。 目标 = 相对当前最优的提升 Δbest；“不注入”单独建模；目标函数 O3 = 在 ĝ(c) ≥ ĝ(rank:5) 的约束下选 token 最少的候选。 B1 = 离线先验（留一任务训练，冻结）；B2 / B3 = 在线贝叶斯线性模型（冷启动 / 用先验热启动），每轮观测到 Δbest 后更新，Thompson 采样；都保留 10% 随机探索。每个 arm 最多替换 8 个 inspiration 槽位，跑到第 50 次迭代。
C1–C3（v3）：图配置再加 mixed 路径（similar → lineage：先跨会话找相似代码，再看它在那个会话里的成功改进；fanout 4/8/16，共 27 种配置、325 个候选）； 目标函数 O4 = ĝ(c)/ĝ(rank:5) − 0.1 · L̂(c)/L̂(rank:5)，L̂ = 每得到一个有效子程序的期望推理秒数 =（a + b·输入 + d·输出 token）/ P̂(valid)，输出 token 与 P̂(valid) 按候选预测；不直接惩罚输入 token。在线模型的先验与噪声按 Δbest 的方差缩放。
D1–D2（O5，BRANE 形式）：c* = argmax P̂(刷新最优 | c) − λ·Ê[输出 token | c]/1000，成本只计输出 token；λ 按预算 B（该任务 rank 的平均输出 token）做对偶更新：平均输出超过 B 时 λ 增大，低于 B 时回落到 0。先验 = math 决策数据 + 该任务自己的 50 次随机探索；D1 = 离线先验（冻结），D2 = 在线热启动（每轮观测后更新 P̂）。

@20 quality：优化器 vs. 固定计划

固定计划的最优 = 7 种固定计划中该任务 @20 最好的那个（事后选出的 oracle）；排序加权 = 平均表现最好的单个固定计划。▲/▼ = 优化器相对排序加权的高低。“运行中 @i” = 还没跑完前 20 次迭代。

每格 = 该 arm 选中这个候选的次数占比；颜色越深占比越高。
