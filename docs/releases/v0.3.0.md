# TriDB v0.3.0 — release notes

**TL;DR** — v0.3.0 adds the native **VSGT stream-prefix executor** to the fused
operator extension (`tjs_vsgt`, ADR-0025) on stock PostgreSQL 16/17 + pgvector. The
legacy `tjs_open` signature and behavior are unchanged, and every v0.2.0 capability
(bounded graph leg, PPR seedless default, MCP server, logical backup/restore,
single-writer contract) carries forward as-is. Existing installs move forward with
`ALTER EXTENSION ... UPDATE`.

Extension versions in this release: `graph_store_am 0.3.0`, `tjs_pg 0.3.0`
(both `.control` files; the release image and the `v0.3.0` tag carry the same stamp).
`graph_store_am 0.3.0` is a **lockstep version bump only** — no SQL object or shared
library change versus 0.2.0 — so one version string covers the whole release
(`tests/test_release_coherence.py`).

## Try it

```bash
docker build -f scripts/pg17/Dockerfile.release -t tridb/postgres-trimodal:pg17 .
docker run -d --name trimodal -e POSTGRES_PASSWORD=secret tridb/postgres-trimodal:pg17
docker exec -it trimodal psql -U postgres \
  -c 'CREATE EXTENSION vector;' \
  -c 'CREATE EXTENSION graph_store_am;' \
  -c 'CREATE EXTENSION tjs_pg;'
```

Full install guide: [`docs/INSTALL_stock_pg.md`](../INSTALL_stock_pg.md).

## What changed

### tjs_pg 0.3.0 — native VSGT stream-prefix executor (ADR-0025)

- New SQL surface (`src/tjs_pg/tjs_pg--0.2.0--0.3.0.sql`):
  `tjs_vsgt(request jsonb, query vector DEFAULT NULL)` (a CustomScan, never a
  FunctionScan/materialize; unsupported call forms fail closed via the
  `tjs_vsgt_support` planner support function), `tjs_vsgt_stats(request_id text)`,
  and the `tjs_vsgt_anchors` frozen anchor-manifest table (marked for
  `pg_dump` via `pg_extension_config_dump`).
- `stream_prefix_v1` emits filtered relaxed HNSW prefixes or graph discovery order.
  It makes **no exact global top-k claim**; see the decision record for the full
  contract: [`docs/decisions/0025-vsgt-native-stream-prefix.md`](../decisions/0025-vsgt-native-stream-prefix.md)
  and [`docs/vsgt_native_interface_v0.3.0.md`](../vsgt_native_interface_v0.3.0.md).
- `tjs_open` (ADR-0008 pinned surface) is byte-unchanged.

### graph_store_am 0.3.0 — lockstep only

No DDL, no C change. `graph_store_am--0.2.0--0.3.0.sql` has an empty DDL body;
`graph_store_am--0.1.0--0.3.0.sql` is the 0.1.0 -> 0.2.0 DDL verbatim.

## Upgrading

```sql
ALTER EXTENSION graph_store_am UPDATE TO '0.3.0';
ALTER EXTENSION tjs_pg UPDATE TO '0.3.0';
```

Direct `0.1.0 -> 0.3.0` scripts ship for both extensions alongside the chained
`0.1.0 -> 0.2.0 -> 0.3.0` path. Install the new shared libraries (`make install`)
before running the UPDATE. Upgrade gate: `scripts/extension_upgrade_test.sh`.

## Honest limits — read before benchmarking

- Everything in the v0.2.0 honest-limits list still applies:
  [`v0.2.0.md`](v0.2.0.md#honest-limits--read-before-benchmarking).
- VSGT is verified on stock PostgreSQL 16/17 only; the PG 13.4 ARM64/CUDA fork
  build is unbuilt-here (GX10-gated), as is the 128 GB headline benchmark.
- VSGT is a read-only statement over a frozen graph; full command-ID visibility
  within a writing command is unsupported (ADR-0025).
